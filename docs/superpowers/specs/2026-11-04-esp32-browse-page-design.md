## 2. 關鍵數據（已用真實 feed 量過）

| 指標 | 實測值 |
| :-- | :-- |
| 7 日內**全部**時段行數 | 4,325 |
| 7 日內**晚上（≥18:00）**行數 | **198** ← 新 feed 就咁細 |
| 晚上涉及場地 | 42 個 |
| 區份 | 18 個（16 個有晚上時段） |
| 新 feed 預計大細 | **約 7 KB** |

→ 記憶體完全冇壓力：198 行 × 9 bytes ≈ **1.8 KB** packed array，
JSON 解析峰值 ~20 KB，解析完即刻釋放。唔使 PSRAM 都夠。

## 3. 新 feed 規格（俾 smartplay-live source 出）

**檔名**：`esp32/evening-7d.json`

```json
{
  "g": "2026-11-04 09:12",
  "d": ["2026-11-04","2026-11-05","2026-11-06","2026-11-07","2026-11-08","2026-11-09","2026-11-10"],
  "sports": ["badminton","basketball","volleyball","tennis","turf-soccer-pitch"],
  "v": ["場地名", "..."],
  "s": ["區名", "..."],
  "r": [[sIdx, vIdx, sportIdx, dateIdx, startMin, endMin, courts], "..."]
}
```

| 欄位 | 意思 |
| :-- | :-- |
| `g` | 生成時間 HKT（版本指紋） |
| `d` | 7 個日期，由今日開始 |
| `sports` | 運動 index 表 |
| `v` | 場地名 index 表（全體 dedup） |
| `s` | 區名 index 表（**18 個全部要有**，冇時段嘅區都要出現） |
| `r` | 行：`[區idx, 場地idx, 運動idx, 日期idx, 開始分鐘, 完分鐘, 場數]` |

**過濾規則（後端做）**：`startMin >= 1080`（18:00）、`courts >= 1`、`dateIdx` 0..6

**同時**：加落 `esp32/index.json` 嘅 `files` array。

**Source 改動**：`esp32/fetch_esp32.py` 加一段（下面有 patch）。
因為個 repo 唔喺呢部機，我會交兩個檔案俾你：
- `patches/fetch_esp32.py`（改好嘅完整檔，直接換）
- `patches/evening-7d.patch`（unified diff，`git apply` 就得）

**ESP32 嘅容錯**：檔案 404 → 瀏覽頁顯示「後端未準備新 feed」，通知頁照常運作。

## 4. 畫面設計

### 4.1 兩個頁面

```
〔通知頁〕 = 現時 v3.0 嘅狀態頁（放場通知器）
〔瀏覽頁〕 = 新增：場地瀏覽器
```

### 4.2 通知頁（改動好少）

```
┌────────────────────────────────────────┐
│ 放場通知器              ● push   19:23  │
├────────────────────────────────────────┤
│                                      │
│             等待放場中                 │
│     晚上 6 點後 · 餘額增加或新時段        │
│                                      │
│  last poll          19:23:04          │
│  next poll          00:42             │
│  feed               2026-11-04 08:03  │

```

│ <  九龍城區   3/16                  19:23│  header

│  04   05   06   07   08   09   10      │  日期 tabs（點一下換日）

├────────────────────────────────────────┤
│ 11月4日 星期三                  3 個時段  │  日子 + 數量
├────────────────────────────────────────┤
│ 18:00-19:00  蒲崗村道體育館          3   │  時段行（點一下開詳情）
│ 19:00-20:00  佛光街體育館            1   │
│ 20:00-21:00  順利邨體育館            2   │
│ 21:30-23:00  安秀道公園              1   │
│ 22:00-23:00  石鼓壟道遊樂場          1   │
│ ...                                    │
├────────────────────────────────────────┤
│ < 上一區          自動 8s >      下一區 > │  footer

**時段行格式**：`[時間範圍 font2 76px][場地名 CJK 16px][場數 badge]`

### 4.6 警報卡蓋住所有頁

**收返返你原本喺邊個頁**（用 `g_returnPage` 記住）。

## 5. 互動設計（觸控分區）

| 位置 | 觸控範圍 | 動作 |
| :-- | :-- | :-- |
| header「<」 | x 0..24 | 返通知頁 |
| header 區名 | x 26..120 | 開區份選擇器 |
| header「3/16」 | x 124..170 | 顯示目前進度（無動作 / 或返第一個區） |
| 日期 tab | y 30..50, x 2+i*28 | 切換該日 |
| 「自動 8s >」 | x 200..314, y 30..50 | 循環間隔：8 → 15 → 5 → 關 → 8 |
| 時段行 | y 68..214 | 開詳情卡 |
| footer 左 | x 0..80 | 上一區 |
| footer 中 | x 80..240 | 暫停 / 繼續自動翻頁 |
| footer 右 | x 240..320 | 下一區 |
| overlay 內 | — | 詳情卡／區份選擇器：點空白或「關閉」返回 |

**自動翻頁**：每 8 秒跳下一個區（16 個區 = 2 分鐘一轉）。
跳之前重繪；到最後一個區就跳返第一個。

## 6. 記憶體 / 效能

| 項目 | 大細 |
| :-- | :-- |
| BrowseData packed rows | 400 × 9 B = 3.6 KB |
| 場地名表 | 120 × 44 B = 5.3 KB |
| 區名表 | 24 × 16 B = 0.4 KB |
| 日期 / 運動表 | ~0.2 KB |
| **靜態 RAM 總加** | **≈ +9.5 KB**（現時 67.5 KB → ~77 KB / 320 KB） |
| JSON 解析峰值 | ~20 KB（解析完 `doc.clear()` 即釋放） |
| 輪播重繪 | 只重繪列表區，唔成屏重繪 → 唔會閃 |

**新 feed 載入時機**：**懶載入** —— 第一次撳入瀏覽頁先拉，之後每 15 分鐘更新一次。
（通知頁開機唔會為咗 7 KB 拖慢啟動。）

## 8. 開放問題（要你揀）

1. **翻頁速度**：預設 8 秒／區（16 區 = 2 分鐘一轉）。想快啲（5 s）定慢啲（15 s）？
2. **自動翻頁要唔要連「日」都自動轉**？提案係**淨係轉區**，日由用戶揀。
   如果想自動轉，即係 16 區 × 7 日 = 112 格，會轉到天昏地暗。
3. **輪播範圍**：全部 18 個區，定係淨係你揀嘅 3 個區（九龍城／黃大仙／觀塘）？
   提案：**全部區都喺選擇器入面，但輪播預設只轉「有晚上時段」嘅區**（16 個）。
4. **feed 檔名**：提案 `evening-7d.json`。你想要 `browse.json` 之類嘅名？
5. **本機 workspace 唔係 git repo**（`D:\Teddy\Opencode\ESP32` 冇 `.git`）。
   要唔要 `git init` + 首次 commit？咁樣以後出 patch / diff / rollback 都方便好多。
